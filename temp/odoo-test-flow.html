  1. 01 · Tiếp nhận

    Nhận workbook và chọn workspace

    User dùng add-in với workbook đang mở hoặc gửi đường dẫn file Excel. Có thể chỉ định các case cần test.

    AI tự mở form cấu hình trên trình duyệt và chạy tác vụ nền theo dõi sự kiện submit.

    Submit → Nạp workspace

    User chọn workspace có sẵn, bổ sung thông tin hoặc tạo workspace mới. AI dùng cấu hình đã chọn để xác định môi trường và phạm vi test.

  2. 02 · Phân tích

    Đánh giá và bổ sung testcase

    AI đánh giá độ rõ ràng, độ đầy đủ, điều kiện trước, vai trò, kỳ vọng và tài liệu. Bổ sung edge case và phương án chuẩn bị dữ liệu để chạy trên các môi trường khác nhau.

    Khi vướng → Tra sitemap trước

    Nạp sitemap để tra màn hình, đường dẫn, model, field và nút. Dùng thêm lịch sử và knowledge để chọn cách làm tiếp.

  3. 03 · Dashboard và hai lượt xác nhận

    Rà soát từng case → Duyệt chạy

    AI mở dashboard sau phân tích và theo dõi sự kiện bằng tác vụ nền. Mỗi case hiển thị testcase gốc, phiên bản sau đánh giá và phân tích của AI.

    Lượt 1. Case có badge Need confirm hiển thị câu hỏi ngay tại case, ví dụ thiếu dữ liệu, cần quyền tạo dữ liệu hoặc thiếu BD. Case đủ căn cứ có badge Ready.

    Lượt 2. User duyệt thực thi phạm vi cuối, gồm các case đã đủ căn cứ.

    Trả lời → Phân tích lại case

    AI đọc lại testcase gốc, feedback và file tham chiếu. Cập nhật phân tích và badge trước khi xin duyệt chạy.

    Bỏ qua → Loại khỏi lượt chạy

    User có thể bỏ qua case thiếu dữ liệu. Dashboard hiển thị lý do và phạm vi đã cập nhật.

  4. 04 · Điều phối và thực thi

    Test trực tiếp trên Odoo

    Một agent Sonnet 5.5 hoặc Sol 6.1 điều phối. Mỗi case giao cho một agent Haiku hoặc Luna. Tối đa 5 agent chạy case đồng thời. Case phụ thuộc chờ điều kiện đầu vào.

    Agent mở browser bằng playwright-cli, đăng nhập đúng profile, giữ session và thao tác trực tiếp như người dùng. Ghi kỳ vọng, thực tế và ảnh bằng chứng.

    Cần bản ghi → Agent dữ liệu

    Nhận yêu cầu từ agent testcase, tra sitemap để xác định model, field bắt buộc và quan hệ, dùng script hỗ trợ để tạo nhanh dữ liệu rồi trả định danh.

    Agent bị kẹt → Điều phối hỗ trợ

    Các agent trao đổi khi có yêu cầu. Điều phối đánh thức agent và bổ sung sitemap, lịch sử hoặc knowledge để xử lý nguyên nhân trước khi thử lại. Sai lệch sản phẩm đã xác nhận được ghi FAIL cùng bằng chứng.

  5. 05 · Script regression

    Tạo script sạch cho từng case

    Dựng lại đường chạy từ các thao tác đã kiểm chứng. Giữ phần chuẩn bị, thao tác đúng và assertion. Loại thao tác dò đường, nhầm menu, nhập sai, retry và chờ cứng. Chờ theo trạng thái cần kiểm tra.

    Nhận cấu hình server và profile khi chạy. Case bấm nút nghiệp vụ, sửa, xóa hoặc đổi trạng thái chuẩn bị bản ghi test rồi dùng định danh vừa tạo. Chỉ tạo bản ghi đối chiếu khi cần so sánh.

    Case visual thuần mở giao diện, kiểm tra và chụp bằng chứng trực tiếp. Nếu cần quan sát một trạng thái phụ thuộc dữ liệu, chỉ chuẩn bị phần dữ liệu để đưa màn hình tới trạng thái đó.

    Ví dụ · Mở bản ghi A

    Tạo bản ghi có đặc tính của A, mở đúng bản ghi vừa tạo rồi kiểm tra kỳ vọng. Tạo thêm bản ghi đối chiếu nếu case cần so sánh.

    Dashboard → Chạy lại từ script

    Nút chạy lại thực thi script đã lưu và ghi kết quả lượt mới. Có thể export script hoặc tải ZIP chứa script và helper cần thiết.

  6. 06 · Đầu ra

    Ghi kết quả về đúng dòng testcase

    Đánh dấu PASS, FAIL và các trạng thái liên quan trên dòng case gốc. Tạo các sheet evidence như hiện tại, gồm bước, kỳ vọng, thực tế và ảnh.

    Gửi đường dẫn → Xuất bản sao workbook gốc

    Ghi kết quả và thêm sheet evidence vào bản sao.

    Add-in → Ghi trực tiếp vào workbook mở

    Cập nhật đúng dòng case và thêm sheet evidence vào file đang mở.

Chi tiết triển khai cần xác định

Cách tính agent dữ liệu trong giới hạn 5 và giới hạn retry. Nghiệm thu replay trên một database harness.
